# Iridium SQL Compatibility Matrix

## Purpose

This document is the current compatibility scoreboard for the project.

## Status values

- `exact`: intended SQL Server-equivalent behavior is implemented and covered
- `compatible subset`: useful support exists, but the surface or semantics are still incomplete
- `shim`: behavior exists mainly to satisfy tooling or client compatibility, not as a full implementation
- `unsupported`: not implemented for the supported scope

This matrix is the high-level subsystem scoreboard. For the **code-verified**
function-by-function inventory (aggregates, window functions, scalar built-ins,
built-in TVFs, system variables, and `sp_*` procedures — enforced by
`crates/iridium_core/tests/tsql_function_parity_doc.rs`), see
[`docs/tsql-function-parity.md`](tsql-function-parity.md).

For partial or unsupported SQL Server areas where the lexer may reserve a
keyword (`Lexical: ✅`) while execution intentionally rejects it
(`Execution: ❌`), see the **Per-Axis Parity Breakdown** section at the bottom
of this document.

The baseline below is seeded from the current README, tests, and explicit code-level limitations. It should be updated alongside feature work.

## Per-Axis Parity Breakdown (Partial & Unsupported Features)

Where a feature is partially supported or intentionally rejected, this table
separates lexical recognition from parser, executor, metadata, and wire support
(consolidated from the former `sql-server-2025-implementation-status.md`):

| Feature / Keyword | Lexical | Parser | Execution | Metadata | TDS Client | Notes |
|---|:---:|:---:|:---:|:---:|:---:|---|
| `BACKUP` / `RESTORE` | ✅ | ❌ | ❌ | — | ❌ | Lexically reserved; `phase7_admin_classification.rs` asserts execution fails |
| `BULK INSERT` | ✅ | ✅ | 📝 | — | ✅ | `SqlBulkCopy` native TDS bulk load supported; `BULK INSERT` file path is a row-by-row shim |
| `CLUSTERED` | ✅ | ✅ | 📝 | ✅ | 📝 | Parsed and cataloged; storage engine is not physically B-tree clustered |
| `COLLATE` | ✅ | ✅ | 📝 | ✅ | 📝 | Per-column metadata + `_CS_`/`_BIN` vs `_CI_` and accent sensitivity (`_AI` vs `_AS`) enforced; full locale sort orders not modeled |
| `UPDLOCK` / `ROWLOCK` / `READPAST` / `HOLDLOCK` / `NOLOCK` / `NOWAIT` / `READCOMMITTEDLOCK` | ✅ | ✅ | ✅ | — | ✅ | Row-level locking with lock-then-recheck, `READPAST` skipping, `NOLOCK` dirty reads, conflicting-hint rejection, and Error `1222` timeout parity verified in 2-session SQL Server 2022 oracle |
| `READ_COMMITTED_SNAPSHOT` / `ALLOW_SNAPSHOT_ISOLATION` (`SNAPSHOT`) | ✅ | ✅ | ✅ | ✅ | ✅ | `ALTER DATABASE ... SET` persisted in catalog & `sys.databases`, non-blocking MVCC reads, 3-way row merge, Error `3960` conflict abort, and Error `3952` when disallowed |
| `SECURITY POLICY` (Row-Level Security) | ✅ | ✅ | ✅ | ✅ | 📝 | `FILTER` & `BLOCK` predicates enforced on `SELECT`/`INSERT`/`UPDATE`/`DELETE` (Error `33504`) and exposed in `sys.security_policies`/`sys.security_predicates` |
| `MASKED WITH` / `UNMASK` (Dynamic Data Masking) | ✅ | ✅ | ✅ | ✅ | 📝 | `default()`, `email()`, `partial()`, `random()`, `datetime()` enforced on reads + `GRANT`/`REVOKE UNMASK` + `sys.masked_columns` |
| `CONTAINS` / `FREETEXT` vs `CONTAINSTABLE` / `FREETEXTTABLE` | ✅ | ✅ | 📝 | ✅ | 📝 | `CONTAINS`/`FREETEXT` predicate evaluation supported; `CONTAINSTABLE`/`FREETEXTTABLE` TVFs unsupported |
| `PARTITION FUNCTION` / `PARTITION SCHEME` / `FILEGROUP` | ✅ | ✅ | 📝 | ✅ | 📝 | Persisted in catalog (`sys.partition_*`, `sys.filegroups`, `sys.data_spaces`); physical partitioned storage routing not implemented |
| `GRANT` / `DENY` / `REVOKE` / `USER` / `ROLE` / `EXECUTE AS` | ✅ | ✅ | ✅ | ✅ | 📝 | Persisted in catalog (`sys.database_*`) and enforced at runtime for `SELECT`/`INSERT`/`UPDATE`/`DELETE`/`EXECUTE` under `EXECUTE AS` |
| `COMPUTE` / `BROWSE` / `READTEXT` / `WRITETEXT` / `UPDATETEXT` | ✅ | ❌ | ❌ | — | ❌ | Deprecated/legacy T-SQL syntax; lexically reserved only |
| `OPENROWSET` / `OPENQUERY` / `OPENDATASOURCE` | ✅ | ❌ | ❌ | — | ❌ | External linked-server rowset TVFs unsupported (`OPENXML` is supported) |
| `REPLICATION` / `SERVICE BROKER` / `SQL AGENT` | ✅ | ❌ | ❌ | ❌ | ❌ | Out of scope for embedded single-node engine |
